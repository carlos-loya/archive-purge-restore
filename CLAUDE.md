# APR (Archive-Purge-Restore)

A Kubernetes-native data-platform component that archives old database
rows to object storage as Parquet files, deletes them from the source,
and restores them on demand. Ships as a Kubernetes operator (`apr-manager`)
plus a CLI (`apr`) that runs the same engine for non-K8s use.

## Build & Test

```bash
make build              # Build CLI binary           → ./apr
make build-manager      # Build operator binary      → ./apr-manager
make all                # Both binaries

make test               # go test ./... -v (unit tests for everything)
make lint               # go vet ./...
make clean              # Remove binaries + bin/

# Operator code generation (run any time api/v1alpha1 types change):
make manifests          # Regenerate CRDs + RBAC from kubebuilder markers
make generate           # Regenerate DeepCopy methods
make helm-sync-crds     # Copy generated CRDs into charts/apr/crds/

# Reconciler envtest suite — runs a real apiserver+etcd locally, no cluster:
make test-envtest       # Downloads kube-apiserver/etcd binaries on first use

# Engine integration tests (requires Docker):
make dev-up             # PostgreSQL 16 + MySQL 8.0 + TimescaleDB
make dev-down
make test-integration   # dev-up + go test -tags integration ./integration/...

# Full kind end-to-end (cert-manager + Postgres + MinIO + chart):
make test-k8s-clean     # Boots kind, deploys everything, runs k8s_test.go, tears down
make kind-up            # Just bring up the cluster (for iterating)
make kind-down

# Container image + chart linting:
make docker-build IMG=apr:dev
make helm-lint
```

**CGO**: `mattn/go-sqlite3` (history backend for CLI mode) requires
`CGO_ENABLED=1`, the Go default.

## Architecture

### Engine isolation contract

`internal/engine`, `internal/format`, and `internal/metrics` are
K8s-unaware (zero `k8s.io/...` or `sigs.k8s.io/...` imports). The
operator and the CLI both invoke the engine via `internal/cluster`
(K8s-aware glue) or directly (CLI). Keep this boundary intact when
adding features.

### Operator binary

`cmd/manager` runs a controller-runtime manager that:
- Watches all four CRDs across all namespaces (cluster-scoped install
  by default — see #67 for namespace-scoped).
- Owns the cron schedule for each `ArchiveRule` itself; spawns archive
  Jobs directly (no `CronJob` indirection). Concurrency is forbidden
  per rule.
- When `--enable-webhooks=true`, serves validating admission webhooks
  on `:9443` with TLS material loaded from `--webhook-cert-dir` (the
  Helm chart mints this via cert-manager).
- Registers APR's Prometheus collectors with controller-runtime's
  metrics.Registry; emits archive/restore counters from the reconciler
  when it observes a finished Job (per-Job watermark annotation
  prevents double-counting).

### Job pod runtime (`apr {archive,restore} --from-cr`)

The operator spawns Jobs that run `/apr archive --from-cr <ns>/<name>`
(or `restore`). Inside the pod:
1. Build a controller-runtime client (in-cluster config).
2. Read the named CR + its referenced DBC + SB.
3. Translate to `config.Config` and build providers via
   `internal/cluster`.
4. Invoke `engine.RunArchive` / `engine.RunRestore`.
5. Patch CR status with the result via `cluster.RecordArchiveResult` /
   `cluster.RecordRestoreResult`.

Credentials reach the pod via env vars projected from the referenced
Secrets — see `internal/controller/common.go` for the env-var ABI.

### Archive algorithm (two-phase with batching)

1. **Extract**: query rows older than `now - daysOnline` in batches of
   `batchSize`, write each batch to Parquet at
   `{db}/{table}/{date}/{runID}_{batch}.parquet.pending`.
2. **Delete**: delete archived rows from source by primary key
   (single-PK uses `IN` in batches of 1000; composite-PK uses OR'd
   conditions in batches of 500). For TimescaleDB, drop fully-expired
   chunks first via `drop_chunks()` for efficiency.
3. **Finalize**: rename `.pending` → final path. Files only reach the
   final state after successful deletion.
4. **On failure**: clean up all `.pending` files; no rows deleted.

Run IDs are the first 8 characters of a UUID, surfaced in
`ArchiveRule.status.lastRunID` and the Parquet filename.

### Restore algorithm

Search storage by `{db}/{table}/{date}/` prefix, optionally filter by
run ID (substring match). Read each Parquet file, extract columns, and
batch-INSERT into the database.

### CRDs at `apr.dev/v1alpha1`

| Kind | Spec highlights | Status highlights |
|---|---|---|
| `DatabaseConnection` | engine, host, port, database, sslMode, credentialsSecretRef | Ready condition |
| `StorageBackend` | type (s3/r2/gcs/filesystem), bucket, region, prefix, endpoint, accountID, credentialsSecretRef | Ready condition |
| `ArchiveRule` | databaseRef, storageRef, table, dateColumn, daysOnline, schedule, batchSize, suspend, maxFailures, historyLimit | activeJobRef, lastJobRef, lastRunRowsArchived, lastRunID, lastRunTime, nextScheduledTime, lastTriggerTime, consecutiveFailures, conditions (Ready/ScheduleValid/Progressing/Degraded) |
| `RestoreRequest` | archiveRuleRef, date, runID, table | jobRef, rowsRestored, startTime, completionTime, conditions (Ready/Progressing/Succeeded/Failed) |

Annotation: `apr.dev/trigger-time` (RFC3339) on an ArchiveRule fires an
immediate run on the next reconcile, deduplicated against
`status.lastTriggerTime`.

### CLI commands (non-K8s mode)

```text
apr archive [rule]                # Manual archive (all rules or one)
apr archive --from-cr <ns>/<name> # Archive driven by a Kubernetes CR (Job-pod entrypoint)
apr restore --rule R [--table T] [--date YYYY-MM-DD] [--run-id ID]
apr restore --from-cr <ns>/<name> # Restore driven by a Kubernetes CR
apr daemon                        # Built-in cron scheduler over YAML rules
apr verify                        # Verify Parquet integrity
apr history [--rule R] [--limit N]
apr validate                      # Validate YAML config
apr version
```

## Conventions

- **Engine isolation** — `internal/engine`, `internal/format`,
  `internal/metrics` MUST NOT import any `k8s.io/...` or
  `sigs.k8s.io/...` packages. The operator path goes through
  `internal/cluster`; the CLI path goes through `cmd/apr`.
- **Identifier quoting**: PostgreSQL/TimescaleDB uses
  `"double_quotes"` with `$N` placeholders; MySQL uses ``backticks``
  with `?` placeholders.
- **TimescaleDB**: embeds the Postgres provider, adds
  `ChunkAwareDeleter` for efficient `drop_chunks()` on hypertables;
  falls back to standard Postgres behavior for regular tables.
- **Errors**: always wrap with `fmt.Errorf("context: %w", err)`.
- **File layout**: interfaces in `provider.go`, implementations in
  `{engine}.go`, tests in `*_test.go` (same package).
- **Reconciler tests** use `internal/controller/suite_test.go`'s
  envtest harness; tests skip cleanly if `KUBEBUILDER_ASSETS` is unset.
- **Webhook validators** use `field.ErrorList` aggregates so users see
  field-pathed `kubectl apply` errors and ALL violations are surfaced
  in one round-trip.
- **Metrics emission** is reconciler-side (manager pod) using a
  per-Job `apr.dev/metrics-emitted=true` annotation as a watermark.
  In-pod Prometheus observations from the engine would be discarded at
  exit.
- **CRD changes** require running `make manifests generate
  helm-sync-crds`; CI fails if `config/crd/bases/` or chart `crds/`
  drift from the API types.
- **Parquet type mapping**: DB types normalize via `normalizeType()`
  in `format/parquet.go` — int/smallint→int32, bigint→int64,
  real→float32, double→float64, bool→bool, everything else→string.
- **Sanitization**: archive path components replace non-alphanumeric
  characters (except `-` and `_`) with `_`.
